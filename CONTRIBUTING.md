# Development

Use a development bot and a separate database. Do not connect tests to a live deployment or publish student access codes in issues, logs or screenshots.

1. Describe the problem or intended behavior in an issue.
2. Create a descriptive branch for that change.
3. Make focused commits and add tests when behavior or security changes.
4. Run the README's checks.
5. Open a pull request explaining the user-visible behavior and validation.

Keep the roadmap honest: planned features are implemented only after their changes are merged and checked.
